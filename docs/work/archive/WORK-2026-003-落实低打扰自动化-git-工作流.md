## 3. 范围与非目标

### 范围

- 新增详细 Git 工作流和长期授权/例外矩阵。
- 更新 AGENTS、CONTRIBUTING、Harness 导航、开发流程、质量闸门、交接和自然语言协议。
- 更新 `$manage-repository-harness`，使 Agent 自动执行安全常规 Git 生命周期。
- 将 Git 工作流文档加入 Harness 必需路径检查。
- 校验 Skill/Harness 并以前向测试验证自动路径和必要询问路径。

### 非目标

- 不配置远端、CI、凭据、分支保护或托管平台模板。
- 不创建初始提交、分支、push、PR、merge、发布或标签。
- 不改变 Easy Markdown 产品面向知识库用户的 Git 设计。
- 不引入托管平台专属依赖或脚本。

## 7. 风险与阻塞

- 已控制风险：路径归属、预脏文件和精确暂存阻止长期授权夹带用户改动。
- 已控制风险：三方策略交集、exact-head、非作者批准、无特权 CI 和机器策略阻止自我授权。
- 已控制风险：URL/rewrite 在网络前预检，秘密为硬阻断，等待中的 CI/评审不转成用户问题。
- 残余风险：当前没有远端、CI 或托管平台，远端查询和原子 merge 只能通过规则/前向模拟
  验证；后续 bootstrap 必须以独立 accepted REQ 配置并实测。
- 阻塞条件：无；本需求范围已完成。启用真实 Git 生命周期属于新的 bootstrap 工作。
- 解除人/条件：不适用。
- 解除后的第一步：负责人需要启用仓库时，建立独立 bootstrap REQ 并确认初始纳入范围。
