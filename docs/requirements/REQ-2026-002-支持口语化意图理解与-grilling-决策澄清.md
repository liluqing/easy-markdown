# REQ-2026-002：支持口语化意图理解与 Grilling 决策澄清

## 1. 问题与证据

当前 Harness 的结构完整，但对话建议仍要求用户主动填写目标、范围、验收和权限模板，
并说出 REQ、WORK、ADR 等内部术语。这把项目管理负担暴露给普通用户，与“用户随性地
口语化沟通，Agent 自动理解和推进”的目标不符。

用户在 2026-07-18 明确提出：口语化输入应成为默认入口；Agent 应主动查证事实、推断意图
并推进项目；只有必要时才按照 Grilling 流程逐个澄清关键决策。

## 2. 目标用户与预期结果

- 目标用户：不希望学习仓库治理术语的产品、开发、测试和项目负责人。
- 预期结果：用户可以像与团队成员对话一样提出目标，Agent 在后台完成上下文恢复、分级、
  建档、计划、实施、验证和交接。
- 成功信号：低风险且意图清晰的请求无需问卷即可推进；高影响歧义按依赖顺序一次只问一个
  决策问题，并给出推荐答案。

## 3. 范围

- 将自然语言和口语化输入定义为 Harness 的默认用户接口。
- Agent 自行从仓库和环境查找事实，不向用户询问可发现信息。
- 明确定义可自动采用的合理假设，以及必须交还用户决定的高影响边界。
- 创建仓库级 `$grilling` Skill，并接入 `$manage-repository-harness`。
- 明确 Grilling 的触发、逐题访谈、推荐答案、共识确认和禁止提前实施规则。
- 保留删除、批量迁移、commit、push、PR、merge 和发布等显式授权边界。
- 更新 Harness 检查和用户交互说明，并进行独立 Agent 前向测试。

## 4. 非目标

- 不要求用户学习或主动维护 REQ、WORK、ADR 状态。
- 不为每个请求启动 Grilling，也不把普通澄清变成冗长访谈。
- 不让 Agent 自行决定产品价值、不可逆操作、安全取舍或授权范围。
- 不实现新的自然语言模型、产品 UI 或远程会话系统。

## 6. 约束、依赖与风险

- 过度推断可能偏离用户真实目标；高影响且多解的内容必须交还用户决定。
- 过度 Grilling 会造成疲劳；只在显式触发或答案会实质改变结果时使用。
- “自动推进”不扩大权限，Git 写操作、发布和破坏性操作仍需明确授权。
- 清晰的负责人自然语言指令可以构成需求接受，但 Agent 必须把解释写入决策记录。
- 用户可以随时停止 Grilling；此时 Agent 记录未决问题，不实施依赖这些决定的工作。

## 7. 方案边界

Agent 先区分事实与决定：事实通过仓库、工具和环境查找；决定才询问用户。意图足够清晰且
风险可控时，Agent 采用可逆的合理假设并自动推进。若涉及产品方向、架构、安全、数据、
迁移、破坏性操作、授权，或存在会导致不同结果的多个合理解释，则进入 `$grilling`。

Grilling 期间可以只读调查，但不得修改实现或执行目标动作；每次只问一个当前依赖问题，
提供推荐答案并等待反馈。所有实质决定明确后，Agent 汇总共同理解，并等待用户最终确认。

## 8. 验收标准

- [x] AC-1：用户无需模板或 Harness 术语，可以用不完整、口语化语言发起项目工作。
- [x] AC-2：Agent 自动读取仓库事实、恢复 active WORK、分级、建档并推进已授权的低风险工作。
- [x] AC-3：授权用户的清晰自然语言指令可记录为需求接受，不要求用户说出 `accepted`。
- [x] AC-4：显式 grill/stress-test 请求或高影响歧义会触发 `$grilling`；一次只问一个问题，
  每题给出推荐答案，事实自行查找，确认共同理解前不实施。
- [x] AC-5：Git 写入、发布、删除和批量迁移等权限不会被“自动推进”隐式扩大。
- [x] AC-6：两个仓库 Skill 通过结构校验，Harness 检查通过，独立 Agent 前向测试符合行为。

## 9. 验证计划

- 运行两个 Skill 的官方结构校验和全仓 Harness 检查。
- 前向测试一个清晰口语化低风险请求，确认 Agent 不要求用户填写模板。
- 前向测试一个高影响模糊请求，确认 Grilling 只提出一个带推荐答案的问题且不执行。
- 审查 Git、破坏性操作和需求接受边界是否仍然明确。
